# Repository guidance

Read the named task file in `docs/tasks/` completely before changing code.

## Boundaries

- `viewer/` is the static GitHub Pages application root. Preserve that deployment boundary.
- `viewer/content/*.json` contains domain data; `viewer/js/` contains viewer behavior.
- `viewer/content/manifest.json` is generated by `viewer/scripts/build-manifest.mjs`. Do not hand-edit it.
- Stable entity IDs are public data contracts. Do not rename them without an explicit migration task.
- Prefer the existing dependency-free HTML, CSS, and JavaScript approach. Do not add a framework, package, backend, or build tool unless the task explicitly requires one.

## Task discipline

- Implement only the named task. Do not begin later tasks opportunistically.
- Modify only files allowed by that task.
- Preserve existing behavior unless the task explicitly changes it.
- Do not invent missing fields, content, or requirements. Stop and report the missing dependency instead.
- Run every verification command in the task and report commands, exit codes, pass/fail totals, changed files, and unresolved items.

## Baseline verification

Run these checks after viewer changes:

```powershell
node --check viewer/js/app.js
node --check viewer/js/data-loader.js
node --check viewer/js/entity-types.js
node --test tests/viewer-baseline.test.mjs
```
