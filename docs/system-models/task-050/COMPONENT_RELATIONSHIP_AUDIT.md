# Component and relationship audit

Status: **TASK-050 research audit; zero production domain edits**

This matrix covers every component role modeled or explicitly rejected by the five dossiers. A relationship is requested only when a concrete Ticket action needs it; physical proximity is not a relationship argument. Symptoms remain public observations where assigning a component would narrow the Candidate set.

## Classification key

| Machine value | Meaning |
| --- | --- |
| `existing_sufficient` | An existing stable Component ID is precise enough for the modeled teaching role. |
| `existing_but_broad` | An existing Component is directionally relevant but collapses a source-significant role or technology distinction. |
| `missing_required` | The pilot cannot express a source-backed component or firmware-bearing role precisely with the current Component catalog. |
| `optional_outside_scope` | The role is real but per-instance detail is intentionally unnecessary for these Tickets. |
| `rejected_unjustified` | A nearby or plausible part was considered but neither source nor Ticket requires it. |
