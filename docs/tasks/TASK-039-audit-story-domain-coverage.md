Measure what the current six Quiet Cascade Matches teach and what the playable/domain catalogs leave unused. Produce a human-readable shift map and machine-readable coverage ledger before choosing expansion cases.

## Required reading

## Coverage model

Pin all counts to exact content/campaign versions and report at least these distinct denominators:

1. complete domain inventory;
2. playable action inventory;
3. supported causal fingerprints/Ticket definitions;
4. campaign-one authored Match inventory; and
5. actual required solution paths.

For each of Shifts 1–6, map exact Ticket/fingerprint, public Symptom, candidate and true Faults, required and optional Tests, Commands, Repairs, Validations, Components, Tools, and Protocols. Distinguish:

- merely present in the global catalog;
- legal/relevant to a Story Ticket;
- required for solvability or Isolation;
- required for Repair/Verify closure;
- mentioned in narrative/training copy; and
- actually exercised by the authored minimal route.

Do not claim a diagnostic is taught because it is globally visible, or a Fault is covered because it appears only as a distractor. Report both unique-object coverage and repeated-practice counts. Treat Commands as their own diagnostic family and state plainly whether any current isolation path requires one.

- `docs/story/coverage/CAMPAIGN_ONE_DOMAIN_COVERAGE.md` with the six-Shift map, numerator/denominator tables, uncovered lists, repetition concentrations, and interpretation limits;
