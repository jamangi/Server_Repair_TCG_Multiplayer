# Candidate-Frozen Example Profile v0.0 — card-game play examples

> **Status: non-authoritative example fixture.** These two deterministic replays do not freeze rules, approve balance, create stable IDs, or assert that authored outcomes occurred in the source cases. They apply the temporary [Candidate-Frozen Example Profile v0.0 decisions](v0.0_ex1_decisions.md) to the exact cards, decks, shuffles, and Tickets in the [shared board and card catalog](v0.0_ex1_board_and_cards.md).

## Reading the ledgers

Both games use the profile without adding a transcript-only rule:

- exactly three active Tickets, <code>Q = 0</code>, score termination disabled;
- a named five-card opening hand, one first-turn draw, and two Actions per turn;
- three Search Tokens and one Refresh Token per Player at setup;
- free Hypothesis revision, one-Action Commit Isolation and Document Live basic actions, plus the zero-Action Document Close resolution;
- team-visible Evidence by default in cooperative play and actor-private Evidence by default in competitive play;
- immediate public Worklog placeholders, with later Documentation enriching the original event in place; and
- no Service Point for closure itself; and
- the [frozen causal-contribution rubric](v0.0_ex1_decisions.md#ex1-rule-012--frozen-causal-contribution-rubric-in-the-fixtures) creates one pending point for the required actionable Isolation and one for its necessary Repair, then settles both only in the atomic closure transaction.

Ledger notation is **H/D/X/B** = cards in Hand / draw Deck / discard / Bench. **A** is Actions remaining; **S/R** is Search / Refresh. Every accepted card action moves one instance to discard unless the action is Document Live, which may recover the documented source instance from discard. No technical Tool card in these games creates an Installed card, so every Bench remains zero; Bench is not an account Equipment slot.

The result labels have narrow meanings:

- **Case-backed** preserves a result reported by the selected real-world account.
- **Adapted** preserves its diagnostic function while translating it to current generic domain records or structured Evidence.
- **Authored fixture** is a deterministic result added to make the Ticket replayable and closable.
- **Synthetic** applies only to the Boot Cable Ticket and does not claim case-study support.

An accepted deepest Isolation creates the fixture's pending Isolation contribution; the Repair that directly matches it and remains necessary on the final path creates the pending Repair contribution. Neither changes score before closure. Immediately after the final passing Verify, the active Player receives the Document Close resolution window even when no Actions remain. A valid close costs zero Actions, settles eligible pending contributions, records closer statistics without awarding a closer point, and ends the turn. If that window is not used, the later active Player may close the ready Ticket for zero Actions.
