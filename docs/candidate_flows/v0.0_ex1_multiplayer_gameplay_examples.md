# Candidate-Frozen Example Profile v0.0 — multiplayer gameplay examples

> **Status: non-authoritative example fixture.** These networked walkthroughs do not freeze rules, approve balance, define a protocol, create stable IDs, or require an implementation. They wrap the exact deterministic replays in the [card-game examples](v0.0_ex1_cards_gameplay_examples.md) with the temporary networking, role, visibility, and presentation choices in the [Candidate-Frozen Example Profile v0.0 decisions](v0.0_ex1_decisions.md). The cards, decks, shuffles, board zones, and Ticket answers come unchanged from the [shared board and card catalog](v0.0_ex1_board_and_cards.md).

## Purpose and replay contract

These examples ask what happens around a card game when people join a Room, explicitly choose to Play or Spectate, become Ready, receive player-safe state, lose and regain a connection, see an intent rejected, and leave Results. They add no card action to either underlying replay.

Every handle beginning **EX1-**, **G1-**, or **G2-** is an example-local, non-contractual replay label. Ledger notation is **H/D/X/B** = cards in Hand / remaining draw Deck / discard / Bench. **A** is Actions remaining and **S/R** is Search / Refresh. A public Worklog placeholder reveals actor, exact card or basic action, Ticket, public target surface, Action cost, and action time. Detailed Evidence follows the authorized projection. These single-actionable-Fault fixtures instantiate the frozen rubric: one pending point for the first eligible final-path Isolation and one for its necessary Repair, settled only at valid closure. Document Close itself costs zero Actions, awards zero Service Points, and retains closer statistics.

The network wrapper observes four boundaries throughout:

1. **Room membership is not a role.** Opening a Room always presents **Play / Spectate / Cancel**. A full Player roster never silently converts a person into a Spectator.
2. **The server commits before presentation.** A client submits an intent ID and expected revision. Only an accepted intent can spend Actions, move a card, change a Ticket, or append a Worklog record.
3. **Snapshots are role-safe.** A Player receives that seat's authorized hand, Hypothesis, and Evidence. A Spectator receives only <code>PUBLIC_MATCH</code>. No client receives a Ticket's server-only answer.
4. **Motion consumes semantic events.** It never decides legality, visibility, timing, or duplicate suppression.

### Shared presentation behavior

| Semantic event | Motion for React example | Reduced-motion and nonvisual equivalent |
| --- | --- | --- |
| Role choice / readiness | A portrait settles into the chosen Player or Spectator row; a readiness ring pulses once only after server acceptance. | Replace role/status text in place, move focus to the accepted row, and announce it. |
| Accepted card action | The card moves Hand → resolution → discard only after acceptance. | Move it instantly and announce card, Ticket, cost, result visibility, and destination. |
| Authorized Evidence | Evidence travels only to the actor Notebook, cooperative team tray, or public Worklog projection. | Insert it under a labeled visibility heading; do not use color, motion, or sound as the only cue. |
| Isolation / machine change | The accepted Isolation settles with its citations; changed machine-state fields crossfade and receive text outlines. | Lock the citation panel immediately and show a textual before/after list. |
| Failed Verify | The failure remains in chronology while a route returns to Diagnosis and prior Repair history stays pinned. | Focus a **Returned to Diagnosis** banner and read the preserved-history summary. |
| Documentation | The original event enriches in place while a new publication link appears at the current end; a valid zero-Action close settles the eligible pending contribution rows. | Add action time, publication time, and publisher without moving the old row; announce closure, contribution settlement, and closer statistic separately. |
| Reconnect | A checklist settles snapshot → revision → unseen events → active controls. | Use the same text checklist with no decorative spinner. |
| Rejection | The rejected control gives one restrained nudge after the error arrives. | Keep everything still, focus the inline reason, and state that nothing changed. |
| Results | Observed → Isolated → Repaired → Verified → Documented → Uncertainty sections reveal after terminal state. | Show all sections immediately and focus **Results**. |

Decorative motion never consumes an authoritative clock. Spectator animation is driven only by public semantic events; it cannot animate a concealed result by inference.
