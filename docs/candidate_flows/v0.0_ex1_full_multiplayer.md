# Candidate flow v0.0 ex1 — full multiplayer journey

> **Status: explicitly non-authoritative example fixture.** This is a structural landing-to-sign-out walkthrough, not a frozen rule, product specification, network protocol, account contract, UI commitment, or claim about the final game. Every <code>EX1-*</code> account value, screen code, request name, dialogue choice, outcome, and Motion treatment below is example-local.

This journey applies the temporary [Candidate-Frozen Example Profile v0.0](v0.0_ex1_decisions.md), uses the exact [board, cards, decks, shuffles, and Ticket outcomes](v0.0_ex1_board_and_cards.md), and expands the competitive match in the [focused multiplayer examples](v0.0_ex1_multiplayer_gameplay_examples.md). The underlying card action ledger is also reconciled in the [card-game examples](v0.0_ex1_cards_gameplay_examples.md).

## Narrative context and player intention

<code>EX1-ACCOUNT-DEV</code> is a returning account. Dev wants a Player seat in a short competitive practice Room, not a silent fallback to Spectator. Their immediate plan is to:

1. inspect the Room before committing;
2. confirm that Bench Hardware is legal and suitable for the published three-Ticket fixture;
3. join only after explicitly choosing **Play**;
4. solve the power Ticket with decisive substitution Evidence;
5. use Sol's thermal Evidence only if Sol pays to publish it;
6. recover cleanly if a network revision makes an intent stale; and
7. review the causal record, return to the Room, leave it explicitly, and sign out.

Sol intends to use Systems Field to investigate Thermal and Boot. Nia intends only to watch. Nia's presence is useful to the design probe because every screen must remain understandable without revealing either Player's hand, private Hypothesis, unpublished Evidence, concealed target, or a server-only Ticket answer.

The match remains a card game with one compact loop:

<pre>
Observe -> revise Hypothesis <-> Test -> Commit Isolation
                                           |
                                           v
                                      Repair -> Verify -> Document
                                                   |
                                        a failure may reopen Diagnosis
</pre>

This particular competitive fixture has no failed Verify; the loop still does not let Repair prove a diagnosis. The separate cooperative fixture exercises the failed-Verify return.

## Authority and visibility legend

| Label | Meaning in this walkthrough |
| --- | --- |
| **Local** | Navigation, filters, previews, open drawers, uncommitted deck choice, and dialogue paging; reversible and not authoritative |

| **Account request** | Authenticated request against an expected account revision |
| **Room request** | Membership, role, seat, selected-deck snapshot, Ready state, rematch preference, or departure against an expected Room revision |

The engine or service commits before presentation. A pending animation is not success, an animation callback never spends an Action, and a rejected intent never becomes a Worklog event.

### Sync checklist and authoritative start

<code>SCR-SYNC</code> checks, in order:

1. authenticated account and current Room membership;
2. explicit role and seat;
3. accepted Room revision and two Ready snapshots;
4. each 30-card multiset and compatible G2 fixture;
5. five opening instances plus a 25-card draw stack for each Player;
6. three active Ticket fixtures and turn order A then B;
7. scores 0–0, H/D/X/B <code>5/25/0/0</code>, Actions not yet opened, Search/Refresh <code>3/1</code>, Bench empty;
8. Dev-private, Sol-private, and public Spectator channels; and
9. semantic-event cursor and deduplication set.

After every check is real and the current safe snapshot is installed, Dev chooses **Enter match** and reaches <code>SCR-MATCH</code>. This final button is a focus/readiness acknowledgement, not a second match-creation request. If the socket drops during sync, Retry fetches and installs one complete safe snapshot; it never redraws or exposes another role's projection.

## Complete three-Ticket match transcript

Free Hypothesis revisions mentioned below move no card, spend no Action, create no Worklog event, and remain private. Every named <code>G2-W*</code> event is server-accepted before its UI treatment. H/D/X/B means hand, draw deck, discard, and Bench. The explicitly example-local causal rubric—not SCORE-001—records one pending point for the first eligible deepest Isolation and one for its necessary matching Repair. A valid zero-Action Document Close in the immediate post-Verify window settles those rows, awards no point for closure itself, records closer statistics, and ends the turn.
