# Candidate flow v0.0 ex1 — Account appearance and Qualification recognition

> **Status: explicitly non-authoritative example fixture.** This walkthrough tests account recognition, cosmetic purchase, appearance preview, and authoritative presentation changes. It does not approve commerce, currencies, cosmetics, profile visibility, account persistence, or UI behavior. Read it with the [Candidate-Frozen Example Profile v0.0](v0.0_ex1_decisions.md) and the [example board, cards, decks, Tickets, and recognition fixtures](v0.0_ex1_board_and_cards.md).

The legacy filename is retained so repository links remain stable. The former account/loadout Equipment concept is intentionally absent: there are no slots, inventory items, Store category, effects, compatibility checks, Ready snapshots, or starting Installed objects for it. All <code>EX1-*</code> handles below are local replay labels, not stable IDs or public data contracts.

## What this synchronized example keeps separate

| Concept | Meaning here | What it is not |
| --- | --- | --- |
| Qualification | Recognition-only honor badge recording a campaign accomplishment or standing | Not purchased, equipped, consumed, installed, ranked, or used as a gate |
| Owned card | Account collection copy that may enter a legal saved deck | Not automatically in a deck, hand, or match |
| Deck entry | Count of an owned card definition in a saved 30-card deck | Not a profile item or physical inventory slot |
| Technical Tool | Reusable domain subject or technical affordance bundled by a card | Not an account item, loadout choice, Qualification benefit, or cosmetic |
| Cosmetic | Account-owned visual presentation with no gameplay effect | Not technical power, deck legality, Ticket access, or matchmaking rank |
| Applied appearance | Authoritative account choice for the displayed cosmetic | Not ownership acquisition and never match state |

Qualifications have no effect on Actions, cards, Tests, Isolation, Repair, Verify, Documentation, Ticket access, story access, deck construction, Room admission, or matchmaking. Pinning a badge changes only profile presentation.

## Narrative context and starting account state

Mara (<code>EX1-ACCOUNT-MARA</code>) has completed First Look orientation and is preparing for a Continuity Rotation shift. They want to review the honor badge that records that history and consider a signal-blue jacket for their portrait. Before changing presentation, they confirm that neither choice touches their two exact decks or a future Ready snapshot.

| Fixture | Private account state | Mechanical boundary |
| --- | --- | --- |
| <code>EX1-QUAL-FIRST-LOOK-SAFETY</code> | Earned honor badge; not currently pinned to public profile | Recognition only; grants no permission or effect |
| <code>EX1-COSMETIC-SIGNAL-BLUE-JACKET</code> | Store-visible and unowned | Appearance only |
| Credits / Parts | <code>1,240 Credits / 85 Parts</code> | Example soft currencies; no real-money purchase |
| Saved decks | Bench Hardware and Systems Field are legal | Independent of recognition and appearance |
| Room / match | None | No Ready snapshot, card instance, resource, Bench, or Worklog exists |

Every authoritative account request carries an example intent ID and expected account revision. Preview actions are Local and reversible. A purchase, profile-display change, or appearance change is presented as committed only after the account result succeeds.

## Flow AR-1 — Inspect, pin, and undo Qualification recognition

### Player desire and plan

Mara wants the First Look badge visible on their profile for the next shift. They plan to read its provenance, confirm its non-mechanical boundary, preview the public profile, commit the display choice, audit unchanged gameplay state, and then exercise a real Undo.

1. **Open My Info from Shift.**

   - **Destination:** <code>SCR-SHIFT -> SCR-MYINFO</code>.
   - **Intent/result:** navigation is Local. No account state changes.
   - **Motion:** <code>M-01</code> preserves identity and dock while the central destination fades and shifts 8 px.
   - **Reduced motion:** replace immediately, focus **My Info**, and announce the route.

2. **Open the Recognition tab.**

   - **Surface:** <code>TAB-RECOGNITION</code> lists the badge as **Earned** with source **First Look orientation**, earned time, campaign-history link, current visibility, and the statement **Honor badge — no gameplay or access effect**.
   - **Boundary:** opening the record neither consumes nor activates it. There is no compatibility or eligibility check.
   - **Recovery:** if the account snapshot is incomplete, show **Recognition sync required** with Retry. The UI does not infer an award.

3. **Preview the badge on the public profile.**

   - **Choice:** select <code>EX1-QUAL-FIRST-LOOK-SAFETY</code>, then **Preview on profile**.
   - **Result:** a watermarked Local preview shows the badge beside Mara's name. Shift, Rooms, lobby, and result history still use the committed profile.
   - **Motion:** <code>M-12</code> shares the badge into the preview.
   - **Reduced motion:** replace the preview and read the badge name, source, proposed visibility, and non-mechanical status.

4. **Commit the profile display.**

   - **Modal:** <code>MOD-PROFILE-RECOGNITION</code> offers **Pin badge** or **Cancel**.
   - **Request:** <code>SetProfileRecognition(EX1-QUAL-FIRST-LOOK-SAFETY, expectedAccountRevision)</code>.
   - **Result:** success advances the account revision and pins the badge as profile presentation only.
   - **Unknown response:** query the account revision and display preference before retry; do not pin locally or submit a duplicate request.

5. **Audit unchanged gameplay and access state.**

   - Both saved decks remain byte-for-byte the same legal 30-card definitions.
   - No collection copy, story checkpoint, Ticket availability, procedure, Room setting, rating, or Ready state changes.
   - No hand, Search Token, Action, score, Worklog event, or Installed object is created.
   - Other people may see only the committed public badge and its recognition description, never Mara's private campaign record.

6. **Undo the profile display.**

   - **Choice:** the success notice offers **Undo pin**.
   - **Request:** a new <code>SetProfileRecognition(null, latestAccountRevision)</code>.
   - **Result:** success removes the badge from public profile presentation while retaining it in private Recognition history.
   - **Boundary:** Undo is a new authoritative event, not deletion of the earned badge or visual rewind.

7. **Exit AR-1.**

   - Mara returns to Shift.
   - **Exit state:** badge earned and unpinned; decks and all gameplay state unchanged.

## Flow AR-2 — Purchase, preview, apply, and undo a cosmetic

### Player desire and plan

Mara wants the signal-blue jacket shown in the Store candidate. They want proof that buying it does not apply it automatically and that applying it cannot change technical ability.

1. **Open Store.**

   - **Destination:** <code>SCR-STORE</code> with **Cards** and **Cosmetics** categories. There is no account-mechanical preparation category.
   - **Balance:** <code>1,240 Credits / 85 Parts</code>.
   - **Intent/result:** navigation and filters are Local; catalog/balance comes from the account snapshot.
   - **Motion:** <code>M-01</code>; reduced motion replaces the route and focuses Store.

2. **Preview the jacket.**

   - **Item:** <code>EX1-COSMETIC-SIGNAL-BLUE-JACKET</code>, price <code>650 Credits</code>, owned count 0, destination **Appearance inventory**, statement **No gameplay effect**.
   - **Result:** Mara's watermarked Local portrait preview changes. Their committed portrait elsewhere does not.
   - **Motion:** <code>M-12</code>; reduced motion replaces the preview and announces item, price, and non-mechanical status.

3. **Confirm the purchase.**

   - **Modal:** <code>MOD-PURCHASE</code> shows item, price, balance before <code>1,240</code>, balance after <code>590</code>, owned count, and **Purchase does not apply appearance**.
   - **Choice:** **Buy**, not **Put off**.
   - **Request:** <code>PurchaseItem(itemId, shownPrice, purchaseIntentId, expectedAccountRevision)</code>.

4. **Recover an unknown network outcome.**

   - **Fixture:** the response times out after submission. The modal reads **Checking purchase** and disables a second Buy.
   - **Recovery:** query the authoritative ledger with the same purchase intent ID.
   - **Committed branch:** if found, install the one success.
   - **Not-committed branch:** if absent, restore Buy and the unchanged balance.
   - **Invariant:** animation never deducts currency, creates ownership, or decides the result.

5. **Install the recovered success.**

   - Owned jacket count becomes 1; Credits become 590; Parts remain 85; account revision advances.
   - Badge history, card collection, saved decks, story checkpoint, Room state, and applied appearance remain unchanged.
   - Store offers **View in My Info** or **Keep browsing**; it does not say Applied.

6. **Open My Info -> Appearance and preview.**

   - **Surface:** <code>TAB-APPEARANCE</code> lists the current appearance and owned jacket.
   - **Comparison:** visual slot and colors only; **Gameplay changes: none**.
   - **Result:** selection remains a Local watermarked preview.

7. **Apply the appearance.**

   - **Request:** <code>SetAppearance(EX1-COSMETIC-SIGNAL-BLUE-JACKET, expectedAccountRevision)</code>.
   - **Result:** success updates the committed portrait in My Info, Shift, Rooms, lobby presence, and later Results.
   - **Motion:** <code>M-12</code> updates shared identity only after success.
   - **Reduced motion:** swap the portrait, focus the confirmation, and announce the appearance.

8. **Undo appearance, then reapply.**

   - **Undo:** a new <code>SetAppearance(previousCosmetic, latestAccountRevision)</code>, not a local rollback.
   - **Reapply:** after the undo succeeds, Mara submits a new request for the signal-blue jacket.
   - **Conflict recovery:** if another surface advances the account revision, reload both committed and preview states before offering a new request.

9. **Exit AR-2.**

   - **Exit state:** Credits 590; Parts 85; jacket owned and applied; First Look badge still earned and unpinned; technical and deck state unchanged.

## Flow AR-3 — Ready-state and technical Tool boundary

### Player desire and plan

Mara enters a Room and checks that only the selected deck is mechanically snapshotted. They also inspect a technical Tool reference to confirm it has not become an account inventory system.

1. **Join and choose Play explicitly.**

   - Room membership and Player role use the multiplayer flow's separate requests.
   - Other members see Mara's public portrait and any pinned recognition, not private inventory or campaign history.

2. **Select a legal deck and become Ready.**

   - Ready snapshots the accepted deck definition and legality.
   - The snapshot contains no Qualification, cosmetic effect, profile badge effect, account-mechanical slot, or starting persistent object.
   - <code>M-03</code> presents Ready only after acceptance; reduced motion updates and announces the status.

3. **Try a stale deck edit.**

   - **Rejected request:** <code>DECK_LOCKED_WHILE_READY</code>.
   - **Invariant:** deck revision, Ready snapshot, hand, match state, profile recognition, and appearance remain unchanged.
   - **Recovery:** **Stay Ready** or **Leave Ready and edit**; no silent Ready change.
   - **Motion:** <code>M-14</code>; reduced motion focuses the reason without a nudge.

4. **Inspect recognition and appearance without implying power.**

   - Read-only profile/appearance panels remain available.
   - This fixture does not submit a presentation change while Ready, avoiding an unsupported Room-presence policy decision.
   - No Qualification or cosmetic can clear Ready, satisfy deck legality, or alter the forthcoming match.

5. **Inspect a technical Tool reference.**

   - From a diagnostic card detail, Mara opens its linked Tool domain record.
   - The Tool describes real technical subject matter or a card-bundled affordance. There is no Buy, Own, Equip, slot, compatibility, Qualification, or Ready control.
   - Closing the reference returns focus to the card detail and changes no state.

6. **Exit AR-3.**

   - Mara remains Ready with the same deck snapshot until explicitly leaving Ready.
   - Jacket and honor-badge presentation remain separate account state; no match instance exists until match creation.

## Failure and recovery matrix

| Failure | Preserved state | Recovery |
| --- | --- | --- |
| Recognition snapshot unavailable | Earned history, profile display, decks | Retry account sync; never infer a badge |
| Profile-display revision conflict | Latest committed profile and Local preview | Reload, compare, submit a new intent |
| Purchase response unknown | No Local balance or ownership assumption | Query by the same intent ID before retry |
| Appearance revision conflict | Latest committed appearance and owned cosmetics | Reload and re-preview; no stale overwrite |
| Mechanical deck change while Ready | Ready snapshot, deck, Room state | Explicitly leave Ready, edit, validate, select, Ready again |
| Cosmetic preview canceled | Prior committed appearance | Discard Local preview with no request |
| Technical Tool record unavailable | Card definition and account state | Retry the reference; do not invent an account item |

## Motion and reduced-motion audit

- <code>M-01</code> changes shell destinations while preserving identity; reduced motion replaces the route and moves focus.
- <code>M-03</code> presents accepted Room role/Ready state; reduced motion updates and announces text.
- <code>M-12</code> distinguishes Local identity, badge, Store, and cosmetic preview from accepted account presentation; reduced motion uses immediate replacement and before/after text.
- <code>M-13</code> reports actual account/ledger synchronization; reduced motion uses the same checklist.
- <code>M-14</code> presents a rejected account/deck request without state change; reduced motion focuses the reason.
- Currency, ownership, recognition, profile visibility, appearance, legality, and Ready state always have text. Color, portrait pose, motion, and sound are supplementary.
- Decorative preview time never consumes an authoritative turn clock.
