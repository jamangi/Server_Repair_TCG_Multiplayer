## Scope and identifier discipline

This is the shared fixture catalog for every focused example and full journey in this package. A later flow may choose a subset of these objects, but it must not silently change their rules, deck counts, Ticket answers, or deterministic draw order.

- Every handle beginning **EX1-** is example-local and non-contractual.
- **EX1-** handles deliberately do not resemble the repository's dotted stable-ID format.
- Every dotted entity ID is an existing draft domain record in <code>viewer/content/*.json</code>.
- A linked domain record supplies technical meaning. It does not promote the example card or Ticket into domain data.
- A phrase marked **authored fixture Evidence** is a deterministic game outcome added for replay. It is not asserted by the cited real-world source.
- A phrase marked **gap-backed fixture content** represents a known missing domain object identified by the case-study pilot.

The five case-backed Tickets preserve the limits recorded in the [v0.1 pilot](../case_studies/README.md). The sixth Ticket is visibly synthetic. No Ticket uses or resolves the reserved technical truth of *The Quiet Cascade*.

## One board, not seven departments

The board is organized around a shared Ticket and its changing evidence record. Observe, Hypothesize, Test, Isolate, Repair, Verify, and Document label what an event contributes; they are not ownership lanes, departments, or a permanently forward-only state machine.

<pre>
┌──────────────────────────── shared match header ────────────────────────────┐
│ score / team score | round + active seat | connection | public resources  │
├──────────── Ticket queue ────────────┬──────── selected Ticket ─────────────┤
│ exactly three jointly actionable     │ symptoms + candidate tray           │
│ Ticket surfaces                      │ machine-state strip                  │
│ public status and reward             │ accepted Isolation + requirements   │
├──────────────────────────────────────┴──────────────────────────────────────┤
│ chronological Worklog: action placeholders enriched in original sequence  │
├────────────────── player A ──────────┬──────────────── player B ────────────┤
│ hand | deck | discard | Bench        │ hand | deck | discard | Bench        │
│ Notebook | Actions | Search/Refresh  │ Notebook | Actions | Search/Refresh  │
└──────────────────────────────────────┴──────────────────────────────────────┘
</pre>

### Shared match header

The header shows the collaboration mode, public Player/Team scores, current round and active seat, public hand/deck counts, public Search/Refresh counts, and connection state. It never shows deck order, another Player's hand, unpublished Evidence, or a hidden Ticket answer.

### Ticket queue

Each of the three Ticket surfaces shows:

- example-local Ticket code and title;
- visible symptoms and admissible scenario context;
- the public authored candidate set;
- public status such as **Diagnosis open**, **Repair ready**, **Awaiting Verify**, **Returned to Diagnosis**, or **Ready to document**;
- one base Service Point and possible one-point Root Cause Bonus; and
- public contributor summaries.

Tickets are shared and jointly actionable. Selecting one changes the detail surface; it does not claim ownership.

### Selected Ticket and machine-state strip

The selected Ticket combines rather than separates:

- visible symptoms and later observations;
- candidate comparison and each authorized Player's Hypothesis marker;
- Evidence citations;
- accepted Isolation records;
- authoritative machine-state changes;
- all Verify attempts, including failures; and
- Documentation completeness.

The **machine-state strip** is an authoritative before/after projection. A Repair can change it from, for example, “Bay 1 member failed” to “Bay 1 replacement installed; rebuild in progress.” That change does not say the explanation is proven. Failed Verify preserves the strip and prior history while returning the Ticket to Diagnosis.

### Candidate tray and acceptance requirements

The candidate tray is public scaffolding, not a truth display. It lists three to five stable Fault IDs, plus an example-local component or cause qualifier where the fixture needs one. A Player's support/rule-out annotations derive only from Evidence visible to that Player or team.

The server holds each authored Isolation requirement. The interface lets the Player cite Evidence and commit; it does not expose unmet hidden clauses or preview whether the chosen candidate is true. A rejected commitment returns only **ISOLATION_NOT_SUPPORTED**.

### Worklog

Every accepted paid action receives an immutable authoritative sequence. Its public placeholder contains actor, Ticket, card/basic-action identity, public target surface, Action cost, and action time. Concealed targets and detailed results remain at their normal visibility.

Documentation enriches the original placeholder in place. A later publication event records publisher and publication time and links back to the earlier sequence. The display never reorders an old action to its publication time. Closed records are immutable.

### Player zones

| Zone | Contents | Default visibility | Movement used here |
| --- | --- | --- | --- |
| Hand | Runtime card instances available to play | Owning Player only; count public | Opening draw, turn draw, Search, or Document recovery adds; play removes |
| Draw deck | Ordered runtime card instances | Server only; count public | Draw removes top; Search removes named card then shuffles; Refresh rebuilds |
| Discard | Resolved one-shot cards | Public | Test, Repair, and Verify cards enter after resolution |
| Bench / installed | Persistent Tools or match-time installed assets | Public identity and status | Starts empty in both audited games |
| Notebook | Evidence, Hypothesis, concealed targets, private annotations | <code>PRIVATE_PLAYER</code> competitive; <code>TEAM</code> cooperative | Test and Hypothesis records enter; Documentation creates public projections |
| Ticket attachment/archive | Persistent machine changes and closed causal record | Public summary; authorized detail | Repair results attach; closed bundle archives |
| Action pips | Two Actions for the active turn | Public | Paid actions consume; unused Actions vanish at turn end |
| Utility resources | Search Tokens and Refresh Token | Public count | Basic utility actions consume; closure replenishes |

Installed cards are not an extra hand. None of the 34 cards below is persistent, so both deterministic card-game fixtures begin and end with an empty Bench. The zone remains defined for the equipping examples and later card candidates.

## Account, collection, deck, equipment, and runtime boundaries

These boundaries prevent one noun such as “card” or “equipped” from silently changing meaning between Store, Decks, My Info, and a match.

| Object | Meaning in this package |
| --- | --- |
| Card definition | One of the 34 **EX1-CARD-*** entries below; shared rules text, not an owned object or stable domain entity |
| Owned card copy | Account collection inventory that permits a saved deck to include a copy; acquisition never auto-edits a deck |
| Deck entry | Example card code plus count in a saved 30-card deck |
| Selected deck | Saved deck selected for a context; Ready snapshots its definition and legality |
| Card instance | One replay-addressed copy created for one match, with owner, controller, and zone |
| Equipment | Separately owned account item; it is not a card copy and never consumes a deck slot |
| Cosmetic | Appearance-only account item with no game effect |
| Qualification | Campaign-earned permission or eligibility; not bought, equipped, drawn, or consumed |
| Installed asset | Match-time persistent object in the Bench, created only when explicit equipment or card text says so |
| Credits / Parts | Example-only fictional soft currencies; never cards and never real-money values |

A Player who is Ready or already in a match cannot commit deck or mechanical-equipment changes. A legal account update may clear Ready before the match; it never mutates the snapshotted match deck. The diagnostic cards below bundle temporary access to any linked Tool or Command needed for that execution, so ordinary technical play does not deadlock on drawing a second enabling card.

## Action and card grammar

Every authoritative intent carries an intent ID, actor, expected match revision, and explicit target. A stale or illegal intent is rejected before cost or card movement and creates no Worklog event.

### Turn sequence

1. Install the latest player-safe snapshot and settle reconnect events.
2. Draw the top card if the draw deck is nonempty.
3. Set Actions to two.
4. Revise a Hypothesis before, between, or after paid actions.
5. Take paid actions whose total printed cost does not exceed remaining Actions.
6. End voluntarily, when Actions reach zero, or when a Ticket closure ends the turn.

### Card intent

<pre>
PLAY &lt;card-instance&gt;
  ON &lt;active-ticket&gt;
  [TARGET &lt;public-candidate-or-authorized-instance&gt;]
  EXPECTING &lt;match-revision&gt;
</pre>

A 0-Action card can be played once per card name in a turn. A 1-Action card leaves one Action; a 2-Action card consumes the ordinary turn budget. Accepted one-shot cards move Hand → Resolution → Discard. The result uses the Ticket's authored outcome matrix, not hidden-state logic printed on the card.

### Basic actions

| Basic action | Cost | Target and result |
| --- | ---: | --- |
| Review / Observe | 0 | Read already authorized Ticket, Worklog, and Notebook state; no authoritative event |
| Revise Hypothesis | 0 | Mark one or two public candidates; accepted only when the marker changes; no truth response |
| Commit Isolation | 1 | Select candidate and cite Evidence; accept or return generic rejection |
| Document Live | 1 | Publish one undocumented action and attached result; recover its source card from discard once |
| Document Close | 1 | Publish the mandatory closure bundle; atomically score, archive, replenish, and end turn |
| Search | 1 + one Search Token | Select one card from own draw deck, add to hand, then deterministic shuffle |
| Refresh | 1 + one Refresh Token | Combine own discard and draw deck, deterministically shuffle; hand/Bench stay |
| Pass / End turn | 0 | End with unused Actions |

Commit Isolation uses Evidence visible to the actor. In cooperative play team Evidence is citable. In competitive play an opponent's private Evidence becomes citable only after Documentation promotes it to <code>PUBLIC_MATCH</code>.

### Card families and common disposition

| Family | Function | Disposition in this fixture |
| --- | --- | --- |
| Test | Produce structured Evidence without changing machine state | Discard after result |
| Command | A named software affordance packaged with its related Test outcome | Discard after result |
| Repair | Change machine state after accepted Isolation | Discard; machine change persists on Ticket |
| Verify | Evaluate an authored post-Repair acceptance condition | Discard; result persists on Ticket |
| Tool / installed | Persistent access or modifier | Grammar defined, but no catalog entry used in the audited games |

## Six Ticket fixtures

Every Ticket begins active and public with its visible setup and candidate set. The answer, unused outcome branches, and authored acceptance requirement are <code>SERVER_ONLY</code>. Detailed executed Evidence follows the profile's competitive/private or cooperative/team default until Documentation. Cards not listed as eligible for a Ticket are rejected before payment with **NO_APPLICABLE_EFFECT**.

Each Ticket awards one base Service Point at closure and has one possible Root Cause Bonus point. The closure report must cite the decisive Evidence, accepted Isolation, every machine-changing Repair in the accepted path, every failed Verify in that path, and all current passing Verify results.
