# Candidate flow v0.0 ex1 — combined product walkthrough

> **Status: explicitly non-authoritative example fixture.** This is a navigable landing-to-logout design probe, not a product specification, rule promotion, commerce contract, campaign canon, network protocol, or UI commitment. It applies the temporary [Candidate-Frozen Example Profile v0.0](v0.0_ex1_decisions.md) and repeats the fixtures from the [board and card catalog](v0.0_ex1_board_and_cards.md) so it can be read on its own.

Every `EX1-*`, screen code, account value, line of dialogue, request name, and Motion treatment in this document is local and non-contractual. The two detailed source journeys are the [full campaign flow](v0.0_ex1_full_campaign.md) and [full multiplayer flow](v0.0_ex1_full_multiplayer.md); this combined view joins their routes and keeps enough state to audit either branch independently.

## What the combined walkthrough proves

One signed-in shell can support two different intentions without confusing account state with match state:

- **Campaign branch:** Mara inspects preparation, receives only admissible story context, works three cooperative Tickets with a player-safe computer technician, reviews the Gate's record, accepts progression, and signs out.
- **Multiplayer branch:** Dev finds a Room, explicitly chooses Play rather than Spectate, locks a legal deck, synchronizes into a competitive three-Ticket match with a public spectator, recovers from a stale intent, returns to the lobby, leaves the Room, and signs out.

Both branches use one troubleshooting rhythm rather than seven departmental gates:

```text
Observe -> Hypothesize <-> Test -> Isolate -> Repair -> Verify -> Document
                         ^                         |
                         `---- failed Verify -----'
```

## State and presentation legend

| Boundary | Meaning here |
| --- | --- |
| **Local** | Navigation, filters, previews, dialogue paging, and uncommitted drafts; reversible and not authoritative gameplay/account state |
| **Account request** | Authenticated request with an intent ID and expected account revision; UI waits for success before presenting a commitment |
| **Room request** | Membership, role, seat, selected-deck snapshot, and Ready request against the current Room revision |
| **Match intent** | Server-authoritative or offline-local-authoritative action with an intent ID and expected match revision |
| **Public** | `PUBLIC_MATCH`; safe for Players, Spectators, story presentation, and accessibility announcements |
| **Private / team** | `PRIVATE_PLAYER` in competitive play or `TEAM` in cooperative play; never inferred by animation or story dialogue |
| **Server only** | Ticket answer, unused result branches, random state, and acceptance requirements that the player-safe projection does not expose |

Material presentation patterns repeat consistently:

| Motion code | Standard presentation | Reduced-motion equivalent |
| --- | --- | --- |
| `M-01` | Persistent dock/portrait; destination fades and shifts 8 px | Replace immediately, focus heading, announce route |
| `M-03` | Portrait moves to a Room seat; status ring pulses once | Update seat/role/Ready text and announce |
| `M-04` | Card shares layout between collection and deck | Update both lists and validator count in place |
| `M-05` | Accepted card moves hand -> resolution -> discard | Move instantly; announce card, cost, result, destination |
| `M-06` | Evidence moves only to its authorized Notebook/team/Public target | Insert under a labeled visibility heading and announce |
| `M-08` | Accepted Isolation settles into a cited commitment panel | Lock panel, move focus, announce fault and citation count |
| `M-09` | Machine state crossfades with changed fields outlined | Replace state and show a textual Changed fields list |
| `M-10` | Failed Verify stays pinned while the route returns to Diagnosis | Show Returned to Diagnosis and preserved-history text |
| `M-11` | Documentation enriches the old Worklog row and links publication time | Insert both timestamps and links without moving the old row |
| `M-13` | Sync/reconnect reflects actual checks and received snapshots | Show the same ordered text checklist; no decorative spinner |
| `M-14` | Rejected intent nudges once and displays its reason | No nudge; focus the error; authoritative state stays unchanged |
| `M-15` | Results reveal causal sections after authoritative completion | Show all sections immediately and focus Results |

No callback spends a resource, reveals Evidence, advances a turn, or completes a request. Color, movement, portrait, sound, and timing are never the sole state carrier. Narrative reading occurs before a match starts or after it stops.
